# 开发计划与业务规则

本文记录已确定的业务规则和开发顺序。领域边界见 [架构设计](architecture.md)，数据关系和接口约定见 [领域与接口约定](domain-contracts.md)。

## 1. 账号与资源归属

- 普通用户使用邮箱和密码注册、登录，注册验证和密码找回共用邮件验证流程。未登录时可以浏览公共 Agent 的名称、介绍和能力，创建 Agent、发起对话和读取历史需要登录。
- 管理员在首次部署时初始化，凭证从部署环境注入。公开注册只创建普通用户。
- 首期使用一个平台空间，用户无需创建组织或切换工作空间。
- 公共 Agent 的配置供所有已登录用户使用。每个人的会话、录音、评价和记忆独立归属本人，创建公共 Agent 不获得其使用者的私人数据访问权。
- 管理端默认展示运行状态、错误和资源用量，不提供普通用户对话正文、录音和记忆的浏览入口。
- 用户身份由服务端根据登录状态确定；创建私有 Agent、绑定工具和读取会话时均检查归属及资源权限。

这些规则把账号身份、Agent 的可见范围和对话数据归属分开，公共 Agent 可以共享而不共享用户数据。

## 2. Agent 保存、停用和删除

| 操作 | 行为 |
| --- | --- |
| 首次保存 | 配置校验通过后生成可运行版本，立即可用 |
| 修改后保存 | 新会话采用新版本；已有会话保留原版本，可提示用户新建会话体验新配置 |
| 保存失败 | 返回具体配置错误，原有效配置继续可用 |
| 停用 | 禁止创建会话和继续生成回复，取消正在运行的回复并结束实时连接；已产生的工具结果保留，历史记录仍可查看 |
| 重新启用 | 重新校验当前配置及绑定资源，通过后恢复使用 |
| 删除 | 从 Agent 列表移除并停止运行；使用者的历史记录保留为只读，不级联删除其他用户的数据 |

版本固定只保证配置不被新保存覆盖。Agent 停用、用户权限撤销和工具禁用属于当前有效限制，旧版本不能绕过。旧会话绑定的模型不再可用时明确提示，不自动换模型。

管理员维护公共 Agent，普通用户维护自己的私有 Agent。管理员设置的默认 Agent 若被停用，主对话页展示可用 Agent 供用户选择。

## 3. 文本与 Realtime 会话

同一个 Agent、同一条历史会话允许在文本和实时语音间切换，继续使用同一 Agent 版本。切换到另一个 Agent 时创建新会话。

- 同一会话同一时刻只有一个执行通道。切换前结束或取消当前回复，关闭原实时连接，再启动另一通道；不同会话可以独立运行。
- 平台保存已确认的消息、工具结果和轮次状态。Realtime 连接只是当前通话的连接，不承担长期历史存储。
- 两种通道通过平台保存的历史或摘要交接上下文。音色、供应商内部音频状态和未确认的转写不作为跨通道可恢复状态。
- Agent 可只开启文本，或同时开启文本与 Realtime。移动端按已配置且通过能力校验的通道展示入口。
- Realtime 模型需要支持本 Agent 所需的工具调用、历史输入和中断能力；不满足要求时，在配置阶段明确提示。

### 中断和失败

| 情况 | 行为 |
| --- | --- |
| 用户停止文本生成 | 取消生成，保留已保存内容并标记未完成 |
| 用户打断语音 | 停止播放和生成，清空尚未播放的音频；按播放确认信息记录已听到的内容，中断后的内容不当作已交付回复 |
| 网络断开 | 短暂重连窗口后取消未完成运行；重新进入时读取已保存记录，实时通话重新建立连接 |
| 重复发送 | 识别同一次发送，返回原运行状态，避免重复消息和工具执行 |
| 工具或模型失败 | 明确展示失败状态和重试入口，不伪装成成功回复；涉及数据写入的工具先核对执行结果再决定是否重试 |

具体超时、音频格式和重连事件在接口设计阶段确定。重新连接不承诺恢复供应商内部状态，也不自动重放未确认的音频。

## 4. 工具、记忆与学习反馈

- 两种通道使用同一份工具绑定和同一个服务端工具执行入口。公开 Agent 不扩大用户原有的工具或知识库权限。
- 工具由管理员提供和开放，普通用户从可用列表选择。读取训练记录、评分和查询知识分别属于对应业务能力，不按 Agent 名称分支执行。
- 长期记忆按用户和 Agent 隔离，同一用户与同一 Agent 的多个会话可共享记忆。不同用户即便使用同一个公共 Agent，也不会共享记忆。
- 用户可以查看、更正、删除记忆，并关闭该 Agent 对自己的记忆使用；关闭后停止读取和提取，已有内容可单独清除。
- 删除一条会话时同时移除其专属录音、评价和仅由该会话产生的记忆；有其他有效来源的记忆保留，后台任务不得重新提取已删除内容。
- 普通对话以回复为主。开启评价的 Agent 可以通过工具即时评分，或在一次练习结束后异步生成反馈，结果关联对应消息或录音。
- 发音评价依据实际音频，文本输入不产生发音评分；评价失败显示未完成，不生成占位分数。

## 5. 两端页面职责

| 入口 | 页面及操作 |
| --- | --- |
| Web 管理端 | 管理员登录；公共 Agent 列表、配置、预览和启停；供应商与模型管理；工具、知识库和评价规则管理；账号启停及运行状态查看 |
| 移动端 | 注册、登录和找回密码；公共 Agent 与我的 Agent；私有 Agent 创建、编辑和删除；文本对话与实时通话；会话历史和学习反馈；个人记忆与账号设置 |

Agent 编辑页以名称、描述、提示词和保存为主。模型、工具、知识库、记忆及评价配置按能力分组，提供平台默认选项；用户不需要操作版本发布或接触供应商凭证。

## 6. 开发顺序与验收

每一步完成对应验收再继续，不在基础流程未验证时同时铺开全部模块。

| 顺序 | 工作内容 | 完成条件 |
| --- | --- | --- |
| 1 | 统一领域和接口设计，更新架构及骨架 | 保存即生效、资源归属、停用行为、双通道运行规则一致；形成对应数据关系与接口说明 |
| 2 | 建立本地运行基础 | Go 服务和 worker 能启动与关闭；Docker Compose 中声明的 PostgreSQL、Redis、对象存储完成真实连接验证；补齐配置示例和启动说明 |
| 3 | 实现账号和 Agent 管理 | Web 可维护公共 Agent；移动端可注册登录并维护私有 Agent；越权读取和修改被拒绝；邮件验证使用真实邮件服务验证 |
| 4 | 完成文本对话 | 接入一个实际模型服务，完成流式回复、取消、历史持久化和一个真实业务工具调用；新旧会话采用正确配置版本 |
| 5 | 完成 Realtime 对话 | 接入一个实际 Realtime 服务，完成手机录音、播放、转写、打断、断线处理和文本切换；验证工具执行及上下文延续 |
| 6 | 完成记忆、评价和知识库 | 真实对话验证记忆隔离与删除；真实录音验证评分依据；真实文档验证检索；异步任务重试不重复写入 |
| 7 | 完成整体交付验证 | 公共与私有 Agent 全流程通过；四类英语陪练 Agent 通过配置创建并验证；补齐部署、测试和核心机制消融结果 |

文本和 Realtime 属于完整目标的两条运行链路，前后实现顺序不改变双通道的架构要求。

## 7. 第一批范围

第 1、2 步已完成，第 3 步正在实施。当前已完成账号注册登录、Redis 会话、管理员初始化、公共与私有 Agent 配置保存、不可变版本、启停删除和归属权限校验。`make check` 和 `make integration`（含 race 检查）通过；实际停止 Redis 后，server 和 worker 的 ready 返回 503、live 保持 200，恢复后重新就绪，SIGTERM 正常退出。业务机制的功能验证和消融实验随对应批次实施。

- Agent 定义包含归属和当前版本，配置保存与版本绑定使用原子写入接口。
- 文本执行和实时连接使用独立接口，共用平台事件、已确认历史和资源权限。
- 工具目录接收独立的工具选择参数，由 Agent 侧转换绑定。
- server 和 worker 接入真实基础依赖，提供健康检查和正常关闭；启动方式见 [启动说明](startup.md)。
- 账号和 Agent 管理接口已接入 server，Web 已使用 Ant Design Pro v6 提供对应管理页面；文本模型、Realtime、邮件验证和移动端仍待实现。

## 8. 依赖与验证要求

- 文本模型、Realtime 模型和邮件服务需要真实可用的服务配置；凭证通过环境或安全配置注入，不写入文档或版本库。
- 支持已有协议的云端或本地模型可通过配置接入，绑定前验证实际工具调用、流式输出等能力。
- 业务验证覆盖正常流程及越权、重复请求、取消、断线和停用；编译通过不能替代行为验证。
- 消融实验使用固定数据集，每次只移除一个机制；记录实际指标，不预先宣称评分质量或记忆效果优于对照。
- 当前开发批次覆盖第 3 步的服务端基础能力和 Web Agent 管理；邮件验证、移动端和完整跨用户权限链路仍需继续验证后，再进入文本对话。
