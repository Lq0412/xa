# xa 产品路线图

xa 是通用的个人 Agent 平台。用户注册后拥有默认主 Agent，也可创建专职 Agent；公共 Agent 由管理员维护。人格随 Agent 版本保存，长期记忆以 `memory_items` 存储，`memory.md` 是展示视图。英语口语教练是平台上的一个 Agent。

## 当前状态

截至 2026-11-12，用户已确认本轮验收完成。本轮工具循环、前端配置与恢复、运行追踪及接口约定整理结束，下一阶段进入知识库 RAG。

| 能力 | 已实现内容 |
| --- | --- |
| 运行基础 | server、worker、独立数据库迁移、PostgreSQL / pgvector、Redis、S3 连接与健康检查、一键启停 |
| 账号和 Agent | 注册登录、注册自动创建主 Agent、公共与私有 Agent、不可变配置版本、乐观锁、启停和归属校验 |
| 文本对话 | 百炼适配、NativeEngine 工具循环、运行预算、会话与消息持久化、SSE v1/v2、取消、断线恢复、幂等与审批挂起恢复 |
| 内置工具 | `current_time`、`memory_search`、`memory_write`、`memory_forget`、`tool_result_read`，按 Agent 版本配置权限、审批和限制 |
| 记忆 v2 | 作用域隔离、取代链、核心视图与 HNSW 召回、token 历史窗口、滚动摘要、保持率排序、归档恢复、维护合并和任务重试 |
| 用户端 | 连续对话、Markdown、工具过程与审批、记忆面板、SOUL / 模型 / 工具配置、活动记录 |
| 管理端 | 今天、Agent 列表与整页配置、只读确认记录、运行列表与详情；运行数据仍按当前用户归属限制 |
| 接口约定 | Go / Huma 生成 OpenAPI 3.1，两个前端生成普通 JSON 客户端，SSE 保留标准库 handler 与手写流客户端 |

`kb_search`、`ask_agent` 当前仅有不可用的工具定义，不能检索或执行委派。记忆操作的工具审批已实现；非主 Agent 向用户共享层提交候选记忆的流程仍属于后续范围。

## 后续顺序与验收

| 顺序 | 范围 | 验收重点 |
| --- | --- | --- |
| 1. 知识库 RAG | 上传、解析、切片、向量化、pgvector HNSW 与关键词检索、RRF 融合、Agent 知识库绑定和 `kb_search` | 能查看处理状态与切片；只检索有权访问且已绑定的资料；检索测试对比三种结果；评测输出 recall@5、MRR |
| 2. 文本版口语教练与 FSRS | 配置教练人格、基于资料出题、结构化评分、独立错题卡片和到期复习 | 完成资料出题、作答、纠错、评分、错题记录和后续复习；文本输入不产生发音评分 |
| 3. 主 Agent 委派 | `ask_agent`、子运行上下文隔离、共享记忆授权和候选确认、委派树 | 主 Agent 能委派教练；不读取教练私有记忆；非主 Agent 的共享写入先成为候选；委派深度不超过 2 |
| 4. 质量评测 | 扩展记忆评测集、隔离与投毒测试、消融实验，补齐 RAG 质量结果 | 输出真实的正确率、隔离与投毒指标、token 和延迟；不预设优于对照 |
| 5. 交付整理 | 启动与部署说明、架构图、S1–S6 演示录屏、答辩材料 | 从已记录环境复现完整演示 |

记忆 v2 已包含遗忘排序、摘要、归档和维护合并，后续不重复安排。详细演示目标见 [蓝图](blueprint.md)，运行机制见 [工具循环设计](agent-loop-design.md)，记忆实现见 [记忆 v2](memory-v2.md)。

知识库按已确认的四步推进：R0 设计已确认；R1 [文档摄取](knowledge-ingestion.md) 通过接口和后台验收；R2 实现检索与 Agent 接入；R3 实现页面与质量验收。R2 继续使用不可变 Agent 版本中的 `configuration.knowledge[]`，不新增绑定表；保存绑定与每次检索均校验当前权限。检索范围是版本绑定与调用者当前可读知识库的交集。私有库只能绑定所有者自己的 Agent，公共库只能绑定公共 Agent，绑定不授予额外权限。pgvector 0.8 以上的权限过滤检索需开启 `hnsw.iterative_scan`。

## 边界与取舍

- 当前以 Web 文本交互为主；本轮验收不表示 RAG、口语评分、FSRS、委派或完整 S6 评测已经完成。
- 同一用户与同一 Agent 使用一条连续对话；每轮读取当前配置，运行记录保存实际使用的版本。
- 管理员维护公共 Agent 不获得其他用户对话、记忆和 trace 的读取权。
- 外部文本只作为数据，不能改变权限或直接写入用户共享记忆；遗忘不物理删除事实。
- 每期使用独立分支和一个 PR，由独立验收方 squash 合并；新页面先确认设计，交付附实际截图。

## Icebox

| 条目 | 重新评估的条件 |
| --- | --- |
| Realtime、WebSocket、ASR/TTS | 明确提出语音需求后重新确认范围；目前均未接入 |
| Flutter 移动端 | Web 主线完成后，根据毕设要求决定是否接入 |
| MCP、外部工具市场 | 现有内置工具无法满足明确场景 |
| Rerank | RAG 评测证明候选召回足够而前列排序不足；预选模型为 `qwen3.7-text-rerank` |
| 模型与通用评价后台 | 配置文件及离线评测不能满足实际需求 |
| 多租户、团队空间、细粒度权限与独立审计后台 | 出现明确的多人协作需求 |
| 账号邮件验证、密码找回、反馈与运维中心 | 单独确认账号完善或运营批次 |
| 后台主动 Agent、复习提醒 | FSRS 复习稳定运行且已有通知渠道 |
| 可替换运行内核 | 出现 NativeEngine 无法满足的明确需求，再评估 `Engine` 适配 |

不实现 Agent 自由群聊或无限递归委派。历史占位代码保存在 `skeleton-archive` tag；不按旧目录清单恢复空包或占位页面。
